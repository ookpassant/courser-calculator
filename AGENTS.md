# Repository guidance

## Public copy

Use clear, concise British English. Explain what a tool does and what the user needs to do next. Keep the game’s trait names and rules accurate. Avoid an assistant persona, rhetorical questions, forced jokes, development narratives and repeated explanations. Keep release notes brief and useful to players. Preserve community credits.

Describe privacy accurately: calculations and saved collections are local, but anonymous usage events and submitted feedback can be sent. Parents with matching temperaments are blocked from breeding.

## Commit attribution

The owner wants commits attributed only to their GitHub identity, ookpassant. Do not add assistant authors, assistant co-author trailers, generated-by credits or assistant signatures. Use the owner’s verified repository identity when authorised to commit. Do not rewrite published history without a specific need and a recoverable backup.

## Verification

Run `node tests/run.js` after changing JavaScript. Preserve element IDs, routing hashes, genotype tokens and game mechanics when editing copy. Check tool instructions against the implementation.
